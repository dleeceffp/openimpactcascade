# Terraform Infrastructure for OpenImpactCascade

This directory contains Terraform configurations to provision GCP infrastructure for Vertex AI RAG integration.

## Prerequisites

- Terraform >= 1.0 installed
- GCP account with billing enabled
- `gcloud` CLI authenticated
- Project Editor or Owner role

## Quick Start

### 1. Initialize Terraform

```bash
cd terraform
terraform init
```

### 2. Configure Variables

```bash
# Copy example file
cp terraform.tfvars.example terraform.tfvars

# Edit with your project ID
# terraform.tfvars:
project_id = "your-project-id"
```

### 3. Review Plan

```bash
terraform plan
```

### 4. Apply Configuration

```bash
terraform apply
```

Type `yes` when prompted.

### 5. View Outputs

```bash
terraform output
```

## What Gets Created

- **APIs Enabled:**
  - Vertex AI API
  - Cloud Storage API
  - IAM API

- **Service Account:**
  - Name: `risk-assessment-rag`
  - Roles: `aiplatform.user`, `storage.objectAdmin`

- **GCS Bucket:**
  - Name: `{project-id}-rag-kb`
  - Location: `us-central1` (configurable)
  - Versioning: Enabled

- **Local Files:**
  - `../service-account-key.json` - Service account credentials
  - `../.env.gcp` - Environment configuration

## State Management

### Local State (Default)

Terraform state is stored locally in `terraform.tfstate`.

⚠️ **Important:** 
- Never commit `terraform.tfstate` to version control
- Back up state file regularly
- State contains sensitive information (service account key)

### Remote State (Recommended for Production)

Configure GCS backend:

```hcl
# backend.tf
terraform {
  backend "gcs" {
    bucket = "your-terraform-state-bucket"
    prefix = "openimpactcascade/infra"
  }
}
```

## Security Considerations

### Sensitive Files

Never commit these files:
- `terraform.tfvars` - Contains project ID
- `terraform.tfstate` - Contains service account key
- `../service-account-key.json` - Service account credentials
- `../.env.gcp` - Environment variables

### Service Account Key

The service account key is:
- Generated by Terraform
- Stored in Terraform state
- Written to `../service-account-key.json`
- Base64 decoded automatically

**Best Practice:** Use Workload Identity instead of keys in production.

## Troubleshooting

### "Error: Error creating service account"

- Check you have IAM permissions
- Verify project ID is correct
- Ensure IAM API is enabled

### "Error: Error creating bucket"

- Bucket name must be globally unique
- Try different `bucket_suffix`
- Check Storage API is enabled

### "Error: Insufficient permissions"

Grant yourself required roles:
```bash
gcloud projects add-iam-policy-binding PROJECT_ID \
  --member="user:YOUR_EMAIL" \
  --role="roles/editor"
```

### State Lock Issues

If state is locked:
```bash
# Force unlock (use with caution)
terraform force-unlock LOCK_ID
```

## Migration from Manual Setup

If you already have resources created manually:

### Option 1: Import Existing Resources

```bash
# Import service account
terraform import google_service_account.rag_service_account \
  projects/PROJECT_ID/serviceAccounts/SERVICE_ACCOUNT_EMAIL

# Import bucket
terraform import google_storage_bucket.rag_knowledge_base BUCKET_NAME
```

### Option 2: Fresh Start

```bash
# Delete manual resources
gcloud iam service-accounts delete SERVICE_ACCOUNT_EMAIL
gsutil -m rm -r gs://BUCKET_NAME

# Apply Terraform
terraform apply
```
