fix(results): correct display bugs for low-TEF (sub-annual) risk scenarios

TEF values like 0.01 (once per 100 years) are valid FAIR inputs but exposed
three display bugs in the results page.

Bug 1 — Frequency histogram empty / single bar for TEF < 0.1
  The chart used a fixed binSize of 0.1.  For a TEF max of e.g. 0.12 only
  one meaningful bin was created, and for TEF max < 0.1 freqCounts had
  length 0 and nothing rendered.  Fixed with adaptive binning that selects
  the bin size based on the data range:
    TEF max ≤ 0.05  → binSize 0.005   (e.g. 0.01 TEF → ~10 visible bars)
    TEF max ≤ 0.20  → binSize 0.01
    TEF max ≤ 1.00  → binSize 0.05
    TEF max ≤ 5.00  → binSize 0.25
    otherwise       → ceil(max/20)
  Labels also format correctly at sub-0.1 magnitudes ("0.005 (1 in 200 yrs)").

Bug 2 — "Infinity% change" in controls panel
  The percent-change lines divided originalStats.median and originalStats.p90
  directly.  When TEF < 1 those are both $0 (correct — most years have no
  event) and JS returns Infinity.  Replaced with a zero-safe pctChange()
  helper that shows the absolute dollar delta vs the $0 baseline instead.

Bug 3 — Misleading $0 Typical Year and $0 Bad Year for low-TEF
  The unconditional p50/p90 being $0 is statistically correct but confusing.
  Two additions:
  - A "ℹ️ N% chance of loss year" annotation under the Typical Year stat.
  - A new "Low-Frequency Event — Conditional Loss Context" card (orange
    border, only shown when prob_event < 0.5) displaying the median, mean,
    and 90th-percentile loss *given* that a loss year occurs.

simulation.py
  Added prob_event, conditional_mean, conditional_median, conditional_p90
  to the results dict.  These are computed from the nonzero annual_loss
  slice and passed through to both the initial /analyze render and the
  /recalculate JSON response.
